      <section>
        <h2 class="text-2xl font-bold tracking-tight">2. A fence whose DSL is the page</h2>
        <p class="text-muted mt-2">
          A <code>```likec4</code> fence in an <code>.mdx</code> page is a diagram, not a code
          block. The DSL in the fence is compiled and laid out during the build, so the diagram is
          reviewed in the same diff as the prose around it. Below is a small model of the request
          that produced the page you are reading.
        </p>
      </section>

```likec4 title="The request that rendered this page" height=360
specification { element box }
model {
  browser = box 'Browser'
  cdn = box 'Static host'
  build = box 'Build runner'
  browser -> cdn 'GET /examples/astroc4/'
  cdn -> build 'already built'
}
views { view index { include * } }
```

      <section>
        <p class="text-muted">
          A typo in that DSL fails <code>astro build</code> with the fence's file name and the parser
          message, rather than shipping a blank frame. The layout is memoised by the source text, so
          a page re-rendered during development pays for each distinct snippet once.
        </p>
      </section>

      <section>
        <h2 class="text-2xl font-bold tracking-tight">
          4. LikeC4 source, highlighted without config
        </h2>
        <p class="text-muted mt-2">
          Shiki has no LikeC4 grammar, so astroc4 derives one from LikeC4's own Langium language
          definition and injects it into Starlight's Expressive Code options. There is no
          <code>ec.config.mjs</code> in this repository. A <code>```c4</code> fence shows the source
          rather than drawing it.
        </p>
      </section>

```c4 title="src/likec4/demo.c4 (excerpt)" height=360
specification {
  color brand #8B3DFF
  element actor { style { shape person } }
  element system { style { color brand } }
}

model {
  reader = actor 'Reader'
  site = system 'purview.dev' {
    #public
    icon tech:astro
    docs = service 'Documentation portal' {
      #internal
      technology 'Astro + Starlight'
    }
  }
  reader -[https]-> docs 'reads'
}
```

      <section>
        <h2 class="text-2xl font-bold tracking-tight">5. The details that make it hold up</h2>
        <div class="mt-6 grid gap-5 lg:grid-cols-2">
          <div class="pv-card p-5">
            <h3 class="font-semibold">Icons from the grammar</h3>
            <p class="text-muted mt-2 text-sm">
              <code>tech:astro</code> in the model above is a bundled pack icon. The pack list is
              read from LikeC4's <code>LIB_ICON</code> terminal, so a pack upstream adds highlights
              and renders without a change here. Self-hosted icons stay under <code>public/</code>;
              LikeC4's <code>imageAliases</code> bakes a build-machine <code>file://</code> path into
              the bundle and is deliberately unsupported.
            </p>
          </div>
          <div class="pv-card p-5">
            <h3 class="font-semibold">Translated shell</h3>
            <p class="text-muted mt-2 text-sm">
              The frame headings, badges and error messages come from Starlight's i18n system. A site
              that ships a second locale gets the diagram UI in it for free, and any key can be
              overridden in <code>src/content/i18n/&lt;lang&gt;.json</code>.
            </p>
          </div>
          <div class="pv-card p-5">
            <h3 class="font-semibold">Reproducible highlighting</h3>
            <p class="text-muted mt-2 text-sm">
              This site pins the grammar to <code>v1.60.0</code>. The grammar is fetched once per
              <code>repo@ref</code>, cached and ETag-revalidated; a build that cannot reach
              <code>raw.githubusercontent.com</code> fails by default, or falls back to the bundled
              snapshot with <code>offline: true</code>. <code>ASTROC4_REF</code> overrides the ref
              from CI without editing the config.
            </p>
          </div>
          <div class="pv-card p-5">
            <h3 class="font-semibold">Static by default, hydrated on demand</h3>
            <p class="text-muted mt-2 text-sm">
              The diagram has no useful server-rendered form, so it is a
              <code>client:only="react"</code> island with a placeholder that carries the frame
              height. A static build passes even when islands fail to hydrate, which is why astroc4's
              own CI runs a browser smoke test rather than trusting the exit code.
            </p>
          </div>
        </div>
      </section>
